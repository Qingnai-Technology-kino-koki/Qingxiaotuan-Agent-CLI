# 青小团 CLI → 超越 Claude Code 分阶段路线图

> 制定时间: 2026-08-27。目标不是「功能堆砌对齐」, 而是在三条主线上建立**差异化优势**:
> ① 真实编程能力 ② 安全与可控 ③ 多模型经济。每条线都选 Claude Code 没做透或做重的地方下手。

## 当前基线 (已完成)
- 纯 Python 全栈, 零编译, 模型无关; 10 个纯标准库引擎。
- **最小影响半径护栏**: `safety` 引擎分词+旗标归一+子壳/变量穿透识别红线命令; `ledger` 事务回滚、`/plan` 只读、`/undo`、`/impact`、脱敏审计。
- 多代理 `/swarm`、三层记忆 (SQLite FTS5)、自进化 reflector、cron、10 语言 i18n、TUI 吉祥物状态机。
- 自动模型路由 `router` 已具备 `decide()` 与失败保险 (绝不切到无凭证端点)。
- **本轮新增 (已落地并通过测试)**: `core/auto_route.py` —— 规划用强模型 / 执行用便宜模型 / 卡住自动升级救场的完整闭环, 已接入 agent 主循环并补 9 项测试。工具消息新增 `status` 字段, 供程序化判断成败。

## 阶段一: 把「多模型经济」做成护城河 (1~2 周)
1. **规划/执行分离 + 卡住升级** ✅ 已实现, 需默认开启 + `/route` 增加可视化 (`/route on|off`)。
2. **自动路由默认开启并细化**: 按文件类型/测试覆盖自动选模型; 引入「预算内最便宜胜任模型」策略。
3. **经济学面板**: `/cost` 增加 per-model 耗时/成本对比, 证明「用便宜模型做执行省 X%」。
4. **本地免费模型优先**: 默认把 opencode-zen / 本地 Ollama 作为 tier1 执行模型, 把 API 费用压到最低。

## 阶段二: 把「真实编程能力」做成可信 (2~4 周) — 对标超越核心
1. **可验证的编码闭环**: 每个代码改动后自动跑相关测试/类型检查/lint, 失败则自修复 (已有 reflector, 需接到工具循环)。
2. **大改动预演**: 多文件重构前用 `dry_run` 生成 diff 预览 + 影响面分析, 让用户「先看后批」。
3. **仓库级上下文**: 把 codebase map 与调用图做进长期索引, 减少每轮重复扫描 (当前每次 build map)。
4. **评测基准 (见 `bench/`)**: 本地 SWE 类任务集, 量化 qxt vs Claude Code 的能力/成本/速度差距。

## 阶段三: 把「安全与可控」做成行业最强 (持续)
1. **可逆到操作级**: ledger 支持单文件/单步回滚 + 跨会话回放 (已有基础, 补 UI)。
2. **人工确认分层**: 架构级/破坏性/外部调用分级确认, 支持「本次会话自动批准小改动」。
3. **审计导出合规**: 满足企业审计 (已有 JSONL 脱敏导出, 补保留期/签名)。

## 阶段四: 生态完整度 (发布与扩展)
1. **PyPI 发布** (`pip install qingxiaotuan`)。
2. **公开技能市场**: registry 拉通 + 签名校验。
3. **MCP 广度**: 补齐主流 MCP server 接入样例与文档。
4. **企业级**: SSO/权限/遥测 (可选模块, 默认关)。

## 与 Claude Code 的能力差距与超越路径 (速览)
| 维度 | Claude Code | 青小团现状 | 超越打法 |
| --- | --- | --- | --- |
| 安全护栏 | 权限+确认 | 分词红线+事务回滚+预演 | 把「最小影响半径」做成默认且可视化 (吉祥物 alert) |
| 多模型 | 单一/固定 | 路由+规划/执行分离+卡住升级 | 成本与速度最优, 自动救场 |
| 编码闭环 | 强 | 工具齐全, 缺自动验证 | 接测试/类型/lint 自修复 |
| 记忆 | 会话级 | 三层+FTS5 跨会话 | 已领先, 补仓库级索引 |
| 可移植 | Node 依赖 | 纯 Python 零编译 | 已领先 (轻量/易嵌入) |

## 验收口径
- 每阶段必须有离线测试 (沿用 mock OpenAI server + 真实子进程 e2e)。
- 阶段二必须有 `bench/` 量化对比, 否则不算「超越」。
- 全量测试在本机全绿 (注意: 本机 pytest 临时目录清理受安全删除批量守卫影响, 跑测请用全新 `--basetemp`)。
